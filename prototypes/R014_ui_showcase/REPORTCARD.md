## Architecture Decisions

### Static UI Descriptors, Dynamic Content

**Decision**: UI component types are **static** (7 fixed types), only content is generated by LLM.

**Rationale**:
- Frontend can compile-time optimize widget components
- Type-safe props validation
- Predictable UX patterns
- Backend focuses on content quality, not UI structure

**Implementation**:
```python
# Backend: Returns fixed type + dynamic content
UIDescriptor(
    id="markdown-123",
    type="markdown",  # One of 7 fixed types
    content=generated_content  # Dynamic via DSPy
)
```

### FastAPI + Next.js BFF Pattern

**Decision**: Next.js as "Backend For Frontend", not the API layer.

**Rationale**:
- Keeps backend portable (can be used by mobile, desktop, etc.)
- Frontend handles composition and state management
- Clean separation of concerns

### shadcn/ui + Framer Motion

**Decision**: Use shadcn/ui components with Framer Motion animations.

**Rationale**:
- shadcn/ui: Copy-paste components, full control
- Framer Motion: Declarative animations (200-300ms per spec)
- Tailwind: Utility-first, easy theming

## Widget Gallery

All 7 generative UI widget types are implemented:

### 1. Markdown Block
- **Purpose**: Display formatted text, code blocks, documentation
- **Features**: GFM support, copy button, dismissible
- **Animation**: Fade in (200ms)

### 2. Card Widget
- **Purpose**: Title + content + action buttons
- **Features**: Icon support, multiple actions, variant styling
- **Animation**: Slide up + fade (300ms)

### 3. Form Widget
- **Purpose**: Multi-field user input
- **Features**: text, email, textarea, select fields
- **Animation**: Scale in (250ms)

### 4. Progress Widget
- **Purpose**: Long-running task status
- **Features**: Determinate/indeterminate modes, status text
- **Animation**: Expand (200ms)

### 5. Action Widget
- **Purpose**: Single-call-to-action button
- **Features**: Multiple variants (default, destructive, outline)
- **Animation**: Bounce on hover (150ms)

### 6. Confirmation Widget
- **Purpose**: Destructive action confirmation
- **Features**: Confirm/cancel buttons, risk level styling
- **Animation**: Scale + fade (200ms)

### 7. Voice Widget
- **Purpose**: Voice input (deferred)
- **Status**: Component created, not integrated
- **Note**: Requires STT/TTS pipeline

## Known Issues

### 1. Ollama Model Required
**Issue**: Content generation requires Ollama running with gemma3:4b model.
**Workaround**: Start Ollama with `ollama serve` and pull model
```bash
ollama pull gemma3:4b
```

### 2. No Error Handling for DSPy Failures
**Issue**: If DSPy/Ollama fails, generic error returned.
**Fix**: Add retry logic and fallback content.

### 3. Sessions View is Static
**Issue**: Sessions are mock data, not persisted.
**Fix**: Add session persistence layer.

## How to Run

### Prerequisites
1. Ollama running with gemma3:4b model
2. Python 3.11+ with UV package manager
3. Node.js 20+ with npm

### Backend
```bash
cd backend
uv pip install -r requirements.txt
python main.py
# Server runs on http://localhost:8014
```

### Frontend
```bash
cd frontend
npm install
npm run dev
# Server runs on http://localhost:3014
```

### Access
- **Frontend**: http://localhost:3014
